# LLM2·3 평가 절차

> 통합 이전 LLM2·3 패키지의 원본 문서 보존본입니다. 아래 역할·모델·실행 명령·평가 상태는 현재 AI 서버 기준이 아닙니다. 현재 실행과 평가 안내는 [저장소 README](../../README.md)와 [분류 기준](../classification-criteria.md)을 따릅니다.

## 1. 코드·MCP 계약 회귀

~~~sh
uv sync --locked
uv run pytest -q
uv run python -m app.agent.evaluation
~~~

기본 평가기는 실제 모델을 호출하지 않는다.
8개 합성 사례: 정상 인계, 사례 근거 없음, 검색 조건 보완,
다른 모델의 근거, 원문 버전 변경, 색인 버전 변경, 부서 비활성, 이미 사람 검토인 접수.
expected_outcome/expected_department는 평가기에만 보관하고 LLM과 도구에 넣지 않는다.

expected_workflow_matched는 합성 사례의 기대 인계 경로 일치이며 정비 진단 정확도가 아니다.
모델 호출 없이 처리되는 접수/권한 검증 사례와 모델의 판단 사례를 함께 보고하므로
전체 일치율을 모델 추론 정확도로 표현하지 않는다.

## 2. 실제 LLM + 합성 도구

평가 모델은 OpenAI gpt-4o-mini로 선택했다. SDK extra 설치와 키 설정이 필요하다.
이번 버전은 사용자 결정에 따라 실제 API 평가를 생략했다.
--live-model에서만 실제 API를 호출하고 사용량이 발생한다.

~~~sh
uv run python -m app.agent.evaluation --live-model --case supported_handoff
~~~

첫 한 사례에서 다음을 사람이 확인한다.

- 호출마다 question이 다음 판단 조건과 연결되는가.
- 현재 기체의 내부 이력과 다른 기체의 SDR 사례를 구분하는가.
- JASC를 후보로 다루며 확정 원인/ATA/부서와 동일시하지 않는가.
- AMM 참조 맥락을 실제 작업 절차로 확대하지 않는가.
- 정보 부족이면 구체적인 확인 항목을 제시하는가.
- 부서 변경·보완 요청이 증거에 연결되는가.
- 불필요한 조사 반복이나 불필요한 사람 인계가 있는가.

첫 결과가 적절하면 --case 없이 전체 8개를 실행한다.
사례당 실행 한도는 기본 180초, 최대 240초다.
각 결과는 investigation/review/호출 기록/상태/시각/재조사/지연을 남긴다.
token_usage는 현재 수집하지 않아 null이다. 지연·호출 수로 토큰 비용을 대체하지 않는다.
실제 모델을 사용했더라도 자료가 합성이므로 실제 정비나 팀 코퍼스 검색 성능을 검증한 결과는 아니다.

## 3. 실제 팀 MCP 평가

Backend가 준비한 업무 데이터·RAG 데이터, B01~B03 서버, RAG 8102 서버,
Backend 발급 위임 토큰과 검증된 검색 범위가 필요하다.
이 환경은 이 저장소가 임의로 생성·적재하거나 권한을 확장하지 않는다.

동일한 접수·자료 버전을 고정하고 다음을 준비한다.

- 익명화한 입력 신고와 기대 업무 경로/담당 부서.
- 허용되는 근거 ID와 필수 확인 항목.
- 기대 정답은 평가 전용 자료로 보관하고 검색 색인에 넣지 않음.
- 평가용 SDR과 파생 AMM은 evidence_group_id 단위로 함께 분리.

평가 항목: 도구 선택·검색 근거 적합성, 필수 정보 누락,
인용 정확성·범위 위반, 적절한 보류와 불필요한 보류,
부서 인계 정확성, 재조사·복원 후 일관성, 지연·실제 토큰 사용량.
실제 고장 원인 확정·수리 성공·운항 가능 여부의 성능으로 해석하지 않는다.

실제 모델·실제 팀 MCP 평가를 실행하기 전까지 품질 결과는 미평가로 표시한다.
